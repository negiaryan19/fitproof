# Three-minute FitProof demo

## 0:00–0:25 — The problem

Show the intake screen and say: “A marketplace title such as 16GB DDR4 RAM is not enough. FitProof checks the exact laptop, exact module identity and the user’s actual slots, then shows the evidence behind each decision.”

## 0:25–1:10 — One-click investigation

Click **Try the ThinkPad T480 example**. Let the progress events finish. Point out that the progress stream is generated by the backend and that the replay badge is visible because this run uses recorded excerpts, not a disguised live call.

## 1:10–2:10 — Three decisions from one run

Select the Kingston `KCP432SD8/16` candidate and show **Matches checked specifications**. Then select `KVR32N22S8/16` and open **Why rejected?** to show the conflicting check, the laptop requirement, the observed part value, the evidence excerpt and the source link. Finally select the unresolved generic candidate and show **Needs information**; explain that FitProof refuses to guess an exact SKU.

## 2:10–2:35 — User correction

Open **Update your installed configuration**, mark the installed setup unknown, and recheck. The same stored evidence changes the capacity result to unknown, proving that configuration is treated as user input rather than manufacturer evidence.

## 2:35–3:00 — Why this is defensible

Close with: “SerpApi drives device discovery, exact-part resolution and shopping discovery in live mode. AI extracts typed facts from bounded source excerpts. Deterministic Python rules decide pass, conflict or unknown. Every positive claim keeps its source, excerpt and retrieval time.”

For the submitted video, run one fresh live investigation after configuring the real SerpApi and model keys, then disclose the exact provider/model and the recorded replay as a fallback.
